# ADR 0007 — The edit loop, CLI distribution, services API and docs

## Context
ADR 0006 made ceangal a framework an app can live outside of, but using it
still meant cloning this repository to get the CLI, rebuilding by hand
after each edit, reading the sources to learn the API, and calling the
host ABI's pointer-and-length functions to store a setting or fetch a
URL.

## Decision
- **`ceangal dev`** watches the app (its directory without build output
  and VCS folders, plus the asset, web and native paths `ceangal.toml`
  names outside it) by polling a stamp of paths, sizes and mtimes every
  300 ms. A change starts a build once the stamp has stayed the same for
  150 ms: an editor's save can be several writes.
  - Web: a small server in the CLI (`cli/native/dev.rs`, std only) serves
    the build and adds a script to every HTML page. The script polls
    `/__ceangal/version`, reloads on a new build, and covers the page with
    the compiler's output when the build failed. Builds go to a second
    directory that replaces the served one with two renames, so a page
    never loads half a build. Polling rather than WebSocket or SSE keeps
    the server a few dozen lines with no dependencies, and 400 ms is fast
    enough after a build of several seconds.
  - Desktop: build, start, and after each successful rebuild stop the app
    and start the new one. A failed build leaves the running app.
  - `tests/e2e/dev.mjs` drives both on an app `ceangal new` makes: an edit
    reloads the page with the change, a broken edit shows the error, the
    fix clears it, one rebuild per edit. The desktop run checks the
    restart. Both run in the `framework` CI job.
- **The CLI ships as binaries.** A tag `v<version>` (the CLI's `VERSION`
  must match it) runs `.github/workflows/release.yml`. It builds a
  universal macOS binary (lipo of arm64 and x86_64), static Linux
  binaries for x86_64 and aarch64 (musl, so one file runs on every
  distribution), and a Windows binary, and attaches them to the release.
  `install.sh` and `install.ps1` put the binary in `~/.ceangal/bin`. The
  workflow then installs from the release on macOS, Linux and Windows,
  makes an app, and builds it for the web against the tagged framework,
  which the CLI fetches by itself. `ceangal new` pins apps to the CLI's
  own version.
- **`ceangal doctor`** (`tools/doctor.sh`) lists each target's
  requirements with the command or link that provides the missing ones.
- **String-level services**: `ceangal.storage` (values and secrets),
  `ceangal.http`, and on `ceangal` `asset`, `asset_text`, `open_url`,
  `set_title`, `save_file` and `open_text_file`. They wrap the host ABI
  (docs/abi.md §4) so that apps do not handle pointers. The ABI stays as
  it is. `tests/apps/services` exercises them together with an app's own
  Rust and JavaScript extension.
- **Docs**: a guide in `docs/guide` (getting started, UI, `ceangal.toml`,
  CLI, stores and signing, native extensions) and an API reference in
  `docs/api`, generated by `tools/gen_api_docs.py` from the modules' `pub`
  functions, types and the comments above them. CI regenerates the
  reference and fails when the committed one differs.

## Consequences
- The guide's examples are checked only where a test uses the same code
  (`tests/apps/services`, the template, the Todo app). A changed API
  shows up in the generated reference, not necessarily in the guide.
- Almide issues found on the way, with their workarounds:
  - almide/almide#3417: `println` is held until exit in programs built by
    the standard codegen, so `ceangal dev` prints through a Rust helper
    that flushes.
  - almide/almide#3419: a top-level fn with a `Bytes` parameter cannot be
    a value natively. `on_result` handlers go in as lambdas.
  - almide/almide#3420: on wasm, a value-returning extern call in tail
    position sees its `Bytes` argument already freed. Such calls are
    bound to a `let` first, including the playground's HTTP request.
- `ceangal dev` does not keep the app's state across a rebuild (there is
  no hot reload of code into a running instance); state kept in
  `ceangal.storage` survives.
